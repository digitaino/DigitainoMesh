# DigitainoMesh UI/UX + HIG Cohesion Audit — Lead Designer Synthesis

> Read-only audit (no code changed). 17 area + cross-cutting auditors → 177 raw findings, deduped and prioritized below.

## 1. Executive Summary

The app has a genuinely strong design-system *foundation* — `AppColors`, `View+LiquidGlass`, `SNRQuality+Color`, and a shared component library (`CapsuleBadge`, `CountBadge`, `StatusPill`, `CircularGlassButton`, `SheetScaffold`, `NodeAvatar`, `CircularAnnotationView`) — but it is *mid-migration*, so the dominant problem is **under-adoption and local re-implementation of components that already exist**. Three systemic patterns drive almost every finding: (1) sheets, glass effects, and capsule chips are hand-rolled per screen instead of routed through the shared primitives, causing silent drift; (2) iOS-26 `#available` glass branching is duplicated inline in 7+ files despite a centralized helper; and (3) localization is mandatory but entire feature areas (Weather, SignalBars, RepeaterBenchmark, parts of Chats/Tools/Settings) ship raw English. The **maps** are the most user-visible offender and the root of the developer's "buttons do weird things" complaint: four near-duplicate route-map sheets, three incompatible pin/annotation paradigms, control stacks that relocate from bottom-right to top-right between screens, and a Layers menu that dismisses differently per surface. The overall theme is not "bad design" but **fragmentation through copy-paste** — the fix is to finish the migration onto the existing component library and extend it to cover the gaps (maps especially), not to add more one-offs.

## 2. Top Themes

**1. Components exist but aren't adopted — the badge/pill/button family is re-hand-rolled everywhere.** `CountBadge` is duplicated byte-for-byte in `UnreadBadges` (the most visible badge in the app), and `.background(.fill.tertiary, in: Capsule())` / tinted-capsule chips bypass `CapsuleBadge` in ~20 sites (RepeaterSignalListView, BatchSizeChip, SavedPathDetailView, NoiseFloorView, WioNotificationsDiagnosticView, PermissionCard, Weather). Each copy drifts in padding (6/2 vs 8/4 vs 12/6) and fill opacity (0.15 vs 0.18 vs 0.2). **Systemic fix:** add a solid-fill convenience init to `CapsuleBadge`, reimplement `CountBadge` on top of it, and replace every hand-rolled chip with the primitive; the component library must be the *only* place capsule chrome is defined.

**2. Liquid Glass gating is re-implemented inline instead of through `View+LiquidGlass`.** The single highest-leverage materials issue: `GlassButtonModifier` (Contacts), `glassButtonStyle`/`glassProminentButtonStyle` (LineOfSight), `GlassEffectModifier`/`GlassContainerModifier` (RxLogView), `GlassButtonStyleModifier` (SignalSurvey), `sendButtonStyle`/`textFieldBackground`/`inputBarBackground` (ChatInputBar), `CoordinateGlassModifier` (LocationPicker), `ControlsGlassModifier` (ShareLocationPickerSheet), and inline branches in CLIInputAccessoryView all duplicate the centralized helper — and some fall back to `.bordered` instead of `.borderedProminent`, so the iOS-18 appearance is already inconsistent. **Systemic fix:** delete every local glass modifier, route all call sites through the helpers, and add any missing shape/radius overloads to `View+LiquidGlass.swift` once.

**3. Glass is applied to the content layer, against current HIG.** Apple's Materials: Liquid Glass guidance reserves glass for the floating control/navigation layer and prescribes standard materials for content. RxLogView cards, the LocationPicker coordinate readout, ShareLocationPickerSheet info panel, and the ChatInputBar text-field background all glass-fill content-layer surfaces. **Systemic fix:** restrict glass to floating controls (pills, map control stacks, circular buttons, toolbars); switch in-content cards/readouts/text fields to `.regularMaterial`/`.thinMaterial`.

**4. Sheets hand-roll `NavigationStack + title + toolbar` (~3 of ~70 adopt `SheetScaffold`).** This is the *root enabler* of the dismiss-affordance chaos: the same "close this read-only sheet" action appears as `Done` in `.confirmationAction` (trailing), `Done` in `.cancellationAction` (leading), `Close` in `.cancellationAction` (leading), a raw `xmark` glyph, and `Dismiss` — sometimes within one file (TraceResultsSheet). Two L10n namespaces (`L10n.Chats.Chats.Common.done` vs `L10n.Localizable.Common.done`) even risk divergent translations of the same word. **Systemic fix:** migrate sheets onto `SheetScaffold`, bake a standard dismiss (informational sheets = `Done` in `.confirmationAction`; editing sheets = `Cancel`/confirm), and collapse the duplicate L10n keys.

**5. Color tokens are bypassed and have already drifted.** The SNR→color mapping is *triplicated* and the copies disagree (3-tier red collapse in `SNRQuality+Color` vs a distinct 5-tier hex palette duplicated verbatim in `CommunityHexOverlay` and `SurveyMapRepresentable`). Contact pin colors are raw `UIColor` literals that have drifted from `AppColors` (pin coral `#cc7a5c` vs token `#c97d5d`), and the adaptive-power red/orange/green ternary is copy-pasted across 3 SignalBars files. **Systemic fix:** promote `AppColors.SignalQuality` (Color + UIColor, one canonical tier mapping) and `AppColors` UIColor accessors for identity pins; route every renderer through them.

**6. Localization is mandatory but whole areas are raw English.** Weather (zero `L10n` matches across 3 files), SignalBars popover, RepeaterBenchmark, SharedRouteMapSheet, ShareFormatPickerSheet, PathMapGenerator, TrafficHeatmap legend, CommunitySharing, and WioNotifications are essentially unlocalized — including accessibility labels and nav/IA titles (the `ToolSelection.title` enum mixes L10n with literals, so the Tools sidebar is partly untranslatable). **Systemic fix:** sweep these into the String Catalog under existing `L10n.*` namespaces; treat untranslated user-facing strings as build-blocking going forward.

**7. Fixed-point fonts on body copy break Dynamic Type.** Acceptable for glyphs on 44pt controls, but SignalBars (`.system(size:7/8/9`)), Weather (`size:9` legends, `size:40` sky glyph), and the benchmark hop pills (`size:7/8/9`) apply fixed sizes to real text. **Systemic fix:** use the semantic ramp (`.caption2`/`.caption`/`.footnote`) with `minimumScaleFactor`; reserve `.system(size:)` for pure SF Symbol glyphs.

**8. Accessibility gaps cluster on icon-only data and map toggles.** RepeaterCompactRow encodes all signal data in SF Symbols with zero `accessibilityElement`/label; the label-mode toggle in every route-map sheet has no `accessibilityLabel` while the adjacent center button does. **Systemic fix:** combine row children with synthesized labels, and fix the toggle once by extracting the shared route-map control.

### What's inconsistent / confusing

- **Three pin paradigms for the same "repeater on a map":** `CircularAnnotationView` circle-with-triangle (main map, traffic), `MKMarkerAnnotationView` balloon glyphs (route sheets), and SwiftUI `Marker` + translucent bubble (ContactRouteMap). Endpoint icons even disagree: sender = `person.wave.2` teal vs `person.fill` teal; receiver = `iphone.gen3` blue vs `antenna.radiowaves.left.and.right` blue. LineOfSight re-hand-rolls all of it.
- **Control relocation:** SignalSurvey floats its control stack top-right and opens Layers *downward*; every other map is bottom-right opening *upward*. This is the literal "buttons do weird things" — muscle memory breaks between screens.
- **Layers menu behavior varies:** main map has a tap-out scrim; route sheets are bare overlays at a different offset with inconsistent tap-out dismissal; LineOfSight reinvents a custom dimming popover.
- **Fit/center button drifts:** same `arrow.up.left.and.arrow.down.right` glyph, but disabled-when-empty + `.secondary` on the main map, never disabled + `.primary` on route sheets; accessibility copy is literal in some, L10n in others.
- **Every map control button hand-rolls** `Image.font(.system(size:17,weight:.medium)).frame(44x44).contentShape(.rect).buttonStyle(.plain)` with active=`.blue` — 15+ copies, ignoring `CircularGlassButton`; some have a11y labels, some don't.
- **Community filter bar + community cell card duplicated** between MapView and SignalSurvey (cyan `Color.cyan.opacity(0.15)` literals, padding drift 5 vs 7).
- **Time filter has 3 forms:** capsule scroll (main), nav clock Menu (traffic), clock-capsule Menu inside community bar (survey).
- **SNR legend exists on only one map** (TrafficHeatmap); HeardRepeats segments and the community overlay color by SNR with no legend.

### Proposed UNIFIED map spec (extend `MC1/Views/Components`)

1. **One annotation family on `CircularAnnotationView`.** Migrate `RouteEndpointPinView` and the three `LOS*PinView` subclasses onto it; migrate `ContactRouteMapSheet` off SwiftUI `Map{}` onto `RouteMapRepresentable`. One canonical sender/receiver icon+color pair from `AppColors`.
2. **New `MapControlButton`** (`systemImage`, `isActive`, `action`, `accessibilityLabel`) baking 44x44 hit target, `.body` glyph (not `size:17`), `.tint` active state (not `.blue`), and a11y label — required on every button. Compose it inside `MapControlsToolbar`.
3. **Fixed bottom-trailing anchor + upward `LayersMenu` everywhere**, with a shared scrim + tap-out dismissal baked into `MapControlsToolbar` (a `LayersMenuPresenter` modifier). Relocate SignalSurvey to bottom-trailing.
4. **New `RouteMapScaffold`** (built on `SheetScaffold`) owning the loading/empty/content `ZStack`, the info-banner pill (one padding value), and a `RouteMapControlsToolbar` (location + layers + label-mode toggle + fit/center slot). All four route sheets + PathMapGenerator consume it.
5. **One `CommunityFilterBar` + `CommunityCell`** component (chips on `CapsuleBadge`, color from `AppColors`) shared by MapView and SignalSurvey. **One time-filter form** (clock Menu chip) everywhere.
6. **Shared `SNRLegend`** component reading `AppColors.SignalQuality`, with a consistent `info.circle` affordance on every SNR-colored map.
7. **Consistent dismissal:** modal maps → `Close` via `SheetScaffold` (or unify on `Done`); pushed maps → system back chevron, no custom replacement. Delete `GlassButtonStyleModifier`; route survey buttons through `liquidGlassButtonStyle()`.

## 5. Recommended Remediation Sequence

**Phase 1 — Design-system foundation (extend `MC1/Views/Components` + `Extensions`).** Do this first so every later fix snaps to a finished primitive.
- `View+LiquidGlass.swift`: add any missing shape/radius/capsule overloads; then **delete all 8 local glass modifiers** and route call sites through the helpers (resolves the biggest materials drift in one sweep, fixes the `.bordered` fallback divergence).
- `CapsuleBadge`: add a solid-fill init; reimplement `CountBadge` and `RepeaterPickerRow` on top; replace `UnreadBadges` and the ~20 hand-rolled `.fill.tertiary`/tinted chips.
- `AppColors`: add `SignalQuality` (Color+UIColor, one canonical 5-tier mapping), UIColor accessors for contact/repeater/room identity pins, and weather-warning/terrain/metric tokens. Repoint `SNRQuality+Color`, `CommunityHexOverlay`, `SurveyMapRepresentable`, `ContactPinView`, LOS pins.
- Add `.floatingGlassShadow()` helper and a central `Symbols` enum (refresh/resend/sync/reset/ping/disclosure/favorite). Drive `SyncingPillView` from `StatusPillState.systemImageName`; standardize active tint on `.tint`.
- Add a String-Catalog sweep harness for the unlocalized areas (Weather, SignalBars, Benchmark) and collapse the duplicate `Common.done` keys.

**Phase 2 — High-visibility surfaces (maps + sheets).** Build directly on Phase 1 primitives.
- **Maps:** create `MapControlButton`, fold it into `MapControlsToolbar`; bake the Layers menu presentation (anchor + scrim + tap-out) into the toolbar; relocate SignalSurvey to bottom-trailing/upward. Build `RouteMapScaffold` (on `SheetScaffold`) + `RouteMapControlsToolbar` and migrate all four route sheets + PathMapGenerator. Migrate `RouteEndpointPinView`, ContactRouteMap, and the three LOS pins onto `CircularAnnotationView`. Extract `CommunityFilterBar`/`CommunityCell`, one time-filter chip, and a shared `SNRLegend`. Replace `GlassButtonStyleModifier`.
- **Sheets:** migrate the Chats/Contacts/Settings/RemoteNodes/Benchmark/Weather sheet clusters onto `SheetScaffold`; standardize dismiss (informational → `Done` in `.confirmationAction`). Resolve RepeaterStatus/Settings container ownership; migrate status disclosures onto `ExpandableSettingsSection`.
- **Accessibility:** combine RepeaterCompactRow children with synthesized labels (now that the toggle lives in the shared route control).

**Phase 3 — Polish & long-tail.** Lower-risk, lower-visibility cleanups once the system is consistent.
- Content-layer glass → standard materials (RxLog/LocationPicker/ShareLocation/ChatInputBar).
- Dynamic Type: replace fixed-point body fonts (SignalBars, Weather, Benchmark) with the semantic ramp + `minimumScaleFactor`.
- Iconography normalization (refresh/ping/antenna/disclosure/favorite via the `Symbols` enum), settings row `TintedLabel`/destructive convention, one async-action row + one success-feedback pattern.
- Weather refactor: split the 3,497-line monolith into `Weather/Components`, unify `StationCard`, consolidate the two search UIs, remove disabled placeholder menu items, rename `Weather 3` → `Weather` (via Xcode UI per the no-`pbxproj` rule).
- Remaining Low items: shared `CenteredLoadingRow`, `PageDots`, connection-status component, overlay radius/material normalization, onboarding header component, survey navigation consolidation, `WeatherLogView` discoverability.
